## 当前实现状态（2026-04-13 更新）

### GUI 架构状态

当前 GUI 已不再是单一超大文件结构，职责已拆分为：

- `src/gui/runtime.py`
  - 运行时设备解析
  - 视频读取线程
  - 检测线程
  - 预览帧生成与性能统计
- `src/gui/widgets.py`
  - 视频显示控件
  - 稳定视口控件
- `src/gui/presentation.py`
  - KPI、状态栏、分类统计、预警与事件展示映射
- `src/gui/window.py`
  - 主窗口编排
  - 模式切换
  - 参数绑定
  - 启停与交互控制

`src/GUI.py` 当前仅保留程序入口与窗口启动职责。

### 当前 GUI 能力

- 已支持 `自动 / CPU / GPU` 推理设备选择。
- 已支持视频文件模式下的 `720p / 1080p` 工作分辨率档位。
- 视频显示链路已改为“最新帧优先”，主线程主动拉取最新预览帧。
- 已区分并展示：
  - `显示 FPS`
  - `处理 FPS`
  - `模型 FPS`
  - `decode / model / analysis / draw / preview / present`
- 图片模式已移除画面左上角的实时统计叠加，只保留检测框与标签。
- 底部信息区已拆分为：
  - `分类统计`
  - `当前预警`
  - `事件流水`

### 当前稳定运行基线

基于当前代码和最近一次稳定运行截图，当前可参考基线为：

- 显示 FPS：约 `28.4`
- 处理 FPS：约 `23.7`
- 模型 FPS：约 `118.3`
- 平均步长：约 `1.32`
- `decode_ms`：约 `34.4 ms`
- `model_ms`：约 `8.5 ms`
- `analysis_ms`：约 `0.7 ms`
- `draw_ms`：约 `2.6 ms`
- `preview_ms`：约 `6.0 ms`
- `present_ms`：约 `2.3 ms`

### 60FPS 视频准备评审

当前阶段不建议直接承诺“60FPS 原视频实时满帧显示”。原因已经比较明确：

- `模型 FPS` 不是主瓶颈。
- 现阶段优先级应为：
  - `decode`
  - `preview`
  - `draw / 文字渲染`
  - 其他分析逻辑

下一阶段 backlog：

- `P0`：评估 Windows 下 `OpenCV + FFMPEG` 解码链路上限，再决定是否引入 `PyAV / FFmpeg` 或硬解路径。
- `P0`：继续减少每帧缩放与 `QImage/QPixmap` 转换冗余。
- `P1`：做绘制密度自适应，重点控制大量目标时的标签、中文文字、预警标记与轨迹线绘制频率。
- `P1`：对事件与统计刷新做去重，避免高帧率下重复更新相同内容。
